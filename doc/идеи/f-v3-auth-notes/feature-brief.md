# Feature brief (ЧЕРНОВИК) — f-v3-auth-notes

Статус: draft для s01 → вход в s02–s05.
Источник истины: [feature-request.md](./feature-request.md) (неизменяем).
Ветка: `dev/f-v3-auth-notes`, база `8e0e949`. Строго path-10, in-memory, без БД.

## 1. Цель и пользователи

Дать возможность нескольким людям пользоваться «Записной книжкой» на одном
dev-инстансе, не видя чужих заметок.

- **Гость** — не аутентифицирован: видит login/register, любые данные получает
  только после входа. Любой запрос к `/api/notes*` без валидного токена → 401.
- **Зарегистрированный пользователь** — логинится, получает bearer-токен,
  создаёт/читает/удаляет только свои заметки.

Данные живут в памяти процесса: рестарт = полная очистка (users, sessions,
notes). Это осознанно допустимо для dev.

## 2. Scope

### 2.1 API-контракт

Все ответы — JSON (`Content-Type: application/json`), ошибки в текущем стиле
`{"error":"..."}`. Аутентификация — заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Auth | Тело запроса | Успех | Ошибки |
|---|---|---|---|---|---|
| POST | `/api/register` | нет | `{"username":"...","password":"..."}` | 201 `{"id":N,"username":"..."}` | 400 пустые/битые поля, 409 username занят, 405 метод |
| POST | `/api/login` | нет | `{"username":"...","password":"..."}` | 200 `{"token":"<opaque>"}` | 400 пустые поля, 401 неверные данные, 405 |
| GET | `/api/notes` | да | — | 200 `[{"id":N,"text":"..."}]` (только свои) | 401 нет/невалидный/истёкший токен |
| POST | `/api/notes` | да | `{"text":"..."}` | 201 `{"id":N,"text":"..."}` | 400 пустой text, 401, 405 |
| DELETE | `/api/notes/{id}` | да | — | 204 без тела | 400 нечисловой id, 401, 404 нет/чужая, 405 |

Решения по умолчанию (подтвердить в open questions):

- **DELETE чужой заметки → 404**, а не 403: не раскрываем существование чужого id.
- id заметок глобально монотонные, не переиспользуются; принадлежность
  проверяется по `user_id`.
- `401` сопровождается `WWW-Authenticate: Bearer`; тело `{"error":"unauthorized"}`.
- Ограничение тела запроса (например `http.MaxBytesReader`, 1 MiB) — защита от
  мусора, не «фича».

### 2.2 Токен и сессии

- Токен **непрозрачный** (не JWT): 32 случайных байта из `crypto/rand`,
  `base64.RawURLEncoding` (~43 символа).
- Хранится **только на сервере**: `map[token]Session`, в памяти, под тем же mutex,
  что и остальные store-данные.
- TTL: **фиксированный, 24 часа** от логина; истёкшая сессия удаляется при
  обращении и даёт 401. Refresh tokens и sliding expiry — вне scope.
- Logout-эндпоинт в исходном запросе отсутствует (см. open questions).

### 2.3 Модели (in-memory)

```go
type User struct {
    ID           int
    Username     string
    PasswordHash []byte // никогда не сериализуется
    Salt         []byte // никогда не сериализуется
}
type Session struct { Token string; UserID int; ExpiresAt time.Time }
type Note    struct { ID int; UserID int; Text string }
```

У `User`/`Session` поля-секреты помечаются `json:"-"`; наружу отдаются только
`id`/`username`/`text`. Единый `Store` с `sync.Mutex` (как сейчас) — достаточно
для dev-нагрузки.

### 2.4 Хэширование пароля (без внешних сервисов)

**Выбор: PBKDF2-HMAC-SHA256 на stdlib** (`crypto/hmac` + `crypto/sha256`,
~15 строк), соль 16 байт из `crypto/rand`, 210 000 итераций, ключ 32 байта,
сравнение через `crypto/subtle.ConstantTimeCompare`.

Обоснование: `go.mod` без зависимостей, сборка/тесты работают офлайн (важно для
CI path-10); bcrypt потребовал бы `golang.org/x/crypto` и `go mod download`.
PBKDF2-SHA256 — стандарт (NIST SP 800-132), детерминирован для тестов.
`crypto/pbkdf2` появился в stdlib только в Go 1.24, у нас `go 1.23` — поэтому
локальная реализация. Итерации вынести в константу, чтобы s-шаги могли
подстроить под скорость тестов.

## 3. Security-инварианты (обязательны к проверке)

1. `/api/notes*` без заголовка, с мусорным или истёкшим токеном → **401**.
2. User A не видит заметки User B: `GET /api/notes` возвращает только `UserID == A`.
3. User A не удаляет заметку User B → **404** (не 204/403 с подтверждением).
4. Пароли и хэши **никогда** не попадают в JSON-ответы и логи (проверка телом
   ответа: нет полей `password`/`hash`/`salt`).
5. Регистрация с существующим username → **409**, без создания второй записи.
6. Пустые/отсутствующие `username`, `password`, `text` → **400**.
7. Логин с неверным паролем и с несуществующим username → одинаковый **401**
   (не различаем, чтобы не энумеровать пользователей).
8. Токен сравнивается/ищется как ключ map; секреты не логируются.

## 4. UI

Статика без фреймворков (HTML/CSS/JS), 3 страницы:

- `login` — форма username/password, при 200 кладёт токен в
  `localStorage["notebook.token"]`, редирект на notes; показывает 400/401.
- `register` — форма + подтверждение; 201 → редирект на login; 400/409 видны.
- `notes` — при загрузке читает токен, `GET /api/notes`; список, добавление,
  удаление; 401 → очистка токена и редирект на login; 400 показывается рядом
  с формой.

Reload страницы notes сохраняет сессию (токен из localStorage → повторный GET).
Раздача: `go:embed` каталога `web/` либо статика из `web/` (решение — s02/s03),
`e2e.frontend_dir` позже станет `web` (файлы adapter на s01 не трогаем).

## 5. E2E (7 сценариев из запроса)

1. Регистрация нового пользователя.
2. Логин и получение токена.
3. Создание заметки.
4. Reload — заметка видна (сессия сохранилась).
5. Удаление заметки.
6. User B не видит заметку User A.
7. Неавторизованный `GET /api/notes` → 401.

## 6. Out of scope

- БД/персистентность, миграции, DSN; рестарт очищает данные — норма.
- Prod-деплой, canary rollout, `s45.push_primary`, `s46.post_deploy_verify`,
  push в primary.
- Multi-tenant роли/права, admin, sharing заметок.
- Refresh tokens, remember-me, password reset/change, email.
- Rate limiting / lockout / CAPTCHA (для dev не требуются; см. open questions).
- Фреймворки, сборщики, npm-рантайм для UI.

## 7. Открытые вопросы / допущения

1. **DELETE чужой заметки: 404 или 403?** Допущение — 404 (анти-энумерация).
   Если нужен явный 403 — зафиксировать в s02.
2. **Тело ответа register**: ок ли `201 {"id","username"}` (без токена, логин
   отдельным шагом)? Альтернатива — 201 без тела.
3. **TTL токена**: 24h fixed — приемлемо? Нужен ли logout
   (`POST /api/logout`), которого нет в исходном запросе?
4. **Валидация полей**: username 3–32 `[a-zA-Z0-9_-]`, password ≥ 8 символов,
   text 1–4096 — подтвердить или упростить (только non-empty).
5. **Ломающее изменение backend**: текущие `main_test.go` и `/api/notes`
   безавторизационные; после фичи их нужно переписать под auth. Подтвердить,
   что правка тестов входит в scope s-шагов (на s01 не трогаем).
6. **Раздача UI**: `go:embed` (один бинарь, удобно для preview) vs отдача
   каталога `web/` из Go — влияет на `preview-deploy.sh` и Playwright.
7. **Формат ошибок**: сохраняем текущий `{"error":"..."}` для всех кодов?
8. **Rate limiting**: точно вне scope или нужен минимальный лимит на login
   (например 5 попыток/мин на username) как security-инвариант?
9. **Совместимость адаптера**: подтверждаем, что `path1.project.json`
   (`e2e.frontend_dir`, `e2e.command`, `deploy.stand_command`, `audit.*`) и
   `path1.ui.json` обновляются на поздних шагах, не в этом черновике.

## UI wireframes (s03)

Прототип — три статических HTML-страницы (`login.html`, `register.html`,
`notes.html`) + общий `app.js` / `styles.css`, same-origin API `/api/*`,
без фреймворков и сборки. Схемы ниже — «дизайн-намерение» для s04
(`arch/structure/ui-pages/*.yaml`) и s21 (актуализация по коду).

Общие правила макета:

- Контентная колонка: `max-width: 640px`, по центру, `padding: 16px`.
- Один breakpoint **640px**: шире — карточка по центру; уже — одна колонка,
  кнопки full-width, поля на всю ширину.
- Токен: `localStorage["notebook.token"]`. Отображаемое имя в шапке notes —
  `localStorage["notebook.user"]` (значение поля username при логине; не секрет,
  нужно только для подписи, сервер его не возвращает).
- Ошибки — текст в `[role="alert"]`-области с `aria-live="polite"`, не `alert()`.
- Кнопка отправки — `type="submit"`, `Enter` в поле отправляет форму.

### 1. Login (`/login`)

```
+--------------------------------------------------------------+
|  Notebook                                            /login  |
+--------------------------------------------------------------+
|                                                              |
|   Вход                                                       |
|                                                              |
|   Username                                                   |
|   +--------------------------------------------------------+ |
|   | alice                                                  | |
|   +--------------------------------------------------------+ |
|                                                              |
|   Password                                                   |
|   +--------------------------------------------------------+ |
|   | ********                                               | |
|   +--------------------------------------------------------+ |
|                                                              |
|   +--------------------------------------------------------+ |
|   | ! Неверный username или пароль                         | |  <- 401
|   +--------------------------------------------------------+ |
|                                                              |
|   +========================================================+ |
|   |                        Login                           | |
|   +========================================================+ |
|                                                              |
|   Нет аккаунта?  [ Register ]                                |
+--------------------------------------------------------------+
```

Тексты ошибок: `400` — «Username и password обязательны», `401` — «Неверный
username или пароль» (на схеме показан 401; 400 выглядит так же).

Состояния:

```
idle          submit активен, error-область скрыта
submitting    кнопка: [ Logging in... ] disabled, поля disabled
              (повторный Enter/клик не создаёт второй запрос)
error 400     "Username и password обязательны"    — форма сохраняет ввод
error 401     "Неверный username или пароль"       — пароль очищается,
                                                     фокус в Password
success 200   token -> localStorage, username -> localStorage
              location.replace("/notes")  (без записи /login в history)
```

Взаимодействия: `Login` / `Enter` → `POST /api/login`; `200` → `/notes`;
`400`/`401` → inline-ошибка над кнопкой, ввод username сохраняется;
клик `Register` → `/register`. Уже есть валидный токен — при открытии
`/login` всё равно показываем форму (сервер о токене не знает; guard только
на `/notes`), но ссылку «Register» не скрываем.

### 2. Register (`/register`)

```
+--------------------------------------------------------------+
|  Notebook                                         /register  |
+--------------------------------------------------------------+
|                                                              |
|   Регистрация                                                |
|                                                              |
|   Username              (3-32: a-z A-Z 0-9 _ -)              |
|   +--------------------------------------------------------+ |
|   | alice                                                  | |
|   +--------------------------------------------------------+ |
|                                                              |
|   Password              (>= 8 символов)                      |
|   +--------------------------------------------------------+ |
|   | ********                                               | |
|   +--------------------------------------------------------+ |
|                                                              |
|   Confirm password                                           |
|   +--------------------------------------------------------+ |
|   | ********                                               | |
|   +--------------------------------------------------------+ |
|                                                              |
|   +--------------------------------------------------------+ |
|   | ! Passwords do not match                               | |  <- локально
|   | ! Username уже занят                                   | |  <- 409
|   | ! Username: 3-32 символа, a-z A-Z 0-9 _ -              | |  <- 400
|   +--------------------------------------------------------+ |
|                                                              |
|   +========================================================+ |
|   |                       Register                         | |
|   +========================================================+ |
|                                                              |
|   Уже есть аккаунт?  [ Login ]                               |
+--------------------------------------------------------------+
```

`Confirm password` — **только клиентская** проверка (в `POST /api/register`
уходят `username` + `password`). Расхождение → inline-ошибка, запрос не
отправляется (не тратим 400 сервера). Пустой confirm = mismatch.

Состояния:

```
idle          submit активен
submitting    [ Registering... ] disabled + поля disabled
error local   "Passwords do not match" (после blur confirm или submit)
error 400     общая строка про формат полей; подсветка конкретного поля
error 409     "Username уже занят" — фокус в Username, password сохраняется
success 201   показать "Аккаунт создан. Войдите." и через ~0.8s
              перейти на /login (username предзаполнен, фокус в Password)
```

Взаимодействия: `Register` / `Enter` → локальная проверка → `POST /api/register`;
`201` → `/login` с предзаполненным username; `400`/`409` → inline-ошибка,
форма не очищается; клик `Login` → `/login` (ввод теряется — предупреждения нет,
это dev-уровень).

### 3. Notes (`/notes`)

```
+--------------------------------------------------------------+
|  Notebook              alice                  [ Logout ]     |
+--------------------------------------------------------------+
|  Новая заметка                                               |
|  +--------------------------------------------------------+  |
|  | Купить молоко                                          |  |
|  |                                                        |  |
|  +--------------------------------------------------------+  |
|  +--------------------------------------------------------+  |
|  | ! Текст заметки не может быть пустым                   |  |  <- 400
|  +--------------------------------------------------------+  |
|                                          [ Add ]  (disabled  |
|                                          пока поле пустое)   |
+--------------------------------------------------------------+
|  #3  Купить молоко                            [ Delete ]     |
|  ----------------------------------------------------------  |
|  #2  Позвонить в сервис                       [ Delete ]     |
|  ----------------------------------------------------------  |
|  #1  Идея: вынести store в отдельный файл     [ Delete ]     |
+--------------------------------------------------------------+
```

Empty state (после успешного `GET /api/notes` → `[]`):

```
+--------------------------------------------------------------+
|  Notebook              alice                  [ Logout ]     |
+--------------------------------------------------------------+
|  [ форма добавления как выше ]                               |
+--------------------------------------------------------------+
|                                                              |
|          Пока нет заметок. Добавьте первую выше.             |
|                                                              |
+--------------------------------------------------------------+
```

Loading (первый заход / reload):

```
+--------------------------------------------------------------+
|  Notebook              alice                  [ Logout ]     |
+--------------------------------------------------------------+
|  [ форма добавления: disabled до ответа GET ]                |
+--------------------------------------------------------------+
|          Загрузка...                                         |
+--------------------------------------------------------------+
```

Сессия истекла (любой ответ 401 на `GET`/`POST`/`DELETE`):

```
+--------------------------------------------------------------+
|  ! Сессия истекла. Перенаправление на вход...                |
+--------------------------------------------------------------+
|  [ форма и список заблокированы ]                            |
+--------------------------------------------------------------+
```

Состояния:

```
loading        форма disabled, в списке "Загрузка..."
empty          пустой список -> текст empty state
list           элементы #id + text + Delete
submitting add [ Adding... ] disabled, textarea disabled; 201 ->
               поле очищается, фокус в textarea, список дополняется
               элементом из ответа (без полного перезапроса)
error 400 add  inline под textarea, ввод сохраняется
error 401      очистить notebook.token (+ notebook.user), баннер,
               location.replace("/login") — назад на /notes нельзя
error 404 del  "Заметка не найдена" + перезапрос GET /api/notes
delete pending строка приглушена (opacity .5), её Delete disabled;
               204 -> строка удаляется из DOM
```

Взаимодействия:

- Открытие `/notes` / reload: нет токена в localStorage → сразу
  `location.replace("/login")` (без запроса); есть токен →
  `GET /api/notes` c `Authorization: Bearer`, рендер `list`/`empty`.
- `Add` / `Enter` в textarea (Shift+Enter — перенос строки) → `POST /api/notes`;
  `201` → добавить в конец списка (порядок вставки, OD-14), снять empty state.
- `Delete` у своей заметки → `DELETE /api/notes/{id}`; `204` → убрать строку,
  при опустении списка вернуть empty state.
- `Logout` — **клиентский**: удалить `notebook.token`/`notebook.user`,
  `location.replace("/login")`. `POST /api/logout` не вызывается
  (OD-04 = A: эндпоинта нет, сессия на сервере живёт до TTL 24h).
  Кнопка помечена как UI-only, не часть API-контракта.
- Повторный клик во время pending игнорируется (кнопка disabled), текст
  заметки не дублируется.

### 5. Компоненты и состояния (сводно)

| Компонент | idle | loading / disabled | error | success |
|---|---|---|---|---|
| Submit (Login/Register) | активен, текст `Login`/`Register` | disabled, `Logging in...`/`Registering...` | активен снова, ошибка над кнопкой | редирект |
| Add (Notes) | активен при непустом textarea | disabled, `Adding...` | активен, inline 400 | поле очищено, элемент в списке |
| Delete (строка) | активен | строка приглушена, disabled | 404 → строка убрана после refresh | строка удалена |
| Error-область | скрыта | очищена при новом submit | `role="alert"`, текст по коду 400/401/409 | скрыта |
| Список заметок | — | `Загрузка...` | баннер 401 + редирект | `list` или `empty` |
| Токен/guard | есть токен → запрос | — | нет/401 → очистка + `/login` | — |

Правила: одновременно видима **одна** ошибка (новая заменяет старую);
состояние `submitting` блокирует и кнопку, и поля формы, чтобы не было
двойных запросов; ошибки не стирают уже введённый текст (кроме пароля при
401); все переходы — `location.replace`, чтобы «Назад» не возвращал на
страницу с невалидной сессией.

### 6. Потоки

```
/  --302--> /login
/login  --200 + token--> /notes
/login  --Register--> /register
/register --201--> /login (username предзаполнен)
/register --Login--> /login
/notes  --нет токена--> /login            (клиент, без запроса)
/notes  --любой 401--> очистка токена --> /login
/notes  --Logout (клиент)--> удалить токен --> /login
/notes  --reload--> токен из localStorage --> GET /api/notes
```

### 7. Трассировка к контракту

- `login`: поля `username`/`password`, `POST /api/login`, коды 200/400/401,
  ключ `notebook.token`.
- `register`: `username`/`password` + локальный `confirm`,
  `POST /api/register`, коды 201/400/409 → `/login`.
- `notes`: `GET /api/notes` (200/401), `POST /api/notes` (201/400/401),
  `DELETE /api/notes/{id}` (204/400/401/404), header `username` + `Logout`,
  empty state, guard по localStorage. Logout — только UI (OD-04 = A).
- Селекторы для UI-графа s04/s21 (предложение): `#login-form`, `#register-form`,
  `#note-form`, `#note-input`, `#add-note`, `#notes-list`, `#error`/`#form-error`,
  `[data-note-id]`, `#logout`, `#user-name`.
