2. Общее описание

На сайте Кубиков должен появиться раздел «Сверка застрахованных». Пользователь загружает список застрахованных (ЗХ) от страховой компании (СК) в едином шаблоне, система сравнивает его с ЗХ группы компаний (ГК) в системе и показывает расхождения. Результат выгружается в Excel вместе с готовым запросом в текстовом формате для оправки в СК.

Главные правила сверки:

сверяются только ЗХ в статусе «Прикреплен»;

ФИО, программа и номер договора сравниваются точно. Не учитываются только регистр и лишние пробелы. Любое другое отличие — буква (в том числе «е» и «ё»), точка, суффикс — это расхождение: «Москва.» и «Москва..» — разные программы;

дубли и задвоения обязательно показываются.

Требования: загрузка файла (FR-01), сопоставление и категории расхождений (FR-02), экран результата (FR-03), выгрузка в Excel (FR-04).

Отдельно от этой постановки реализуются «История сверок» (список прошлых сверок) и «Договоры и заявки ЗХ в результате сверки» (ссылки на договоры и заявки по каждому ЗХ). Обе опираются на эту постановку.

Как работает

Пользователь открывает раздел, выбирает «Группа компаний*» и «Страховая компания*».

Скачивает шаблон кнопкой «Скачать шаблон» и переносит в него данные СК.

Загружает файл и нажимает «Запустить сверку».

Система проверяет файл. Если есть ошибки, она показывает таблицу ошибок, и сверка не запускается. Если ошибок нет, запускается сопоставление (FR-02) и открывается экран результата (FR-03).

Форма запуска

«Группа компаний*» — список ГК с поиском по названию.

«Страховая компания*» — в списке должны быть только СК, у которых есть договоры с ЮЛ выбранной ГК. Пока ГК не выбрана, поле должно быть неактивно; при смене ГК поле должно сбрасываться.

Область загрузки — должна принимать один файл перетаскиванием или выбором с компьютера; новый файл заменяет предыдущий.

«Скачать шаблон» — всегда активна, должна скачивать пустой файл «Шаблон сверки застрахованных.xlsx».

«Запустить сверку» — должна быть активна, только когда выбраны ГК и СК и загружен файл.

| Колонка | Обяз. | Что заполнять |

| Программа* | да | Название программы дословно, как у СК, со всеми знаками и суффиксами |

Критерии приемки

Раздел «Сверка застрахованных» доступен пользователю; пользователь клиента (HR) раздел не видит.

Пока ГК не выбрана, поле «Страховая компания*» неактивно; после выбора ГК в нем только СК, у которых есть договоры с ЮЛ этой ГК.

«Скачать шаблон» скачивает файл с колонками из таблицы «Шаблон загрузки».

«Запустить сверку» неактивна, пока не выбраны ГК, СК и не загружен файл.

Файл не .xlsx не принимается, отображается E1.

Файл с несколькими ошибками (нет даты рождения в строке 5, неизвестный договор в строке 8) показывает обе ошибки сразу, с номерами строк; сверка не запускается.

Пустые строки в файле ошибкой не считаются.

Файл без ошибок запускает сверку и открывает экран результата.

FR-02. Сопоставление и категории расхождений

| Что нужно сделать | После запуска система должна сопоставить каждую строку файла с ЗХ ГК в системе и отнести каждое несовпадение к категории расхождений. Сверяются только ЗХ в статусе «Прикреплен». Значения сравниваются точно, кроме регистра и лишних пробелов. |

Как работает

Система берет ЗХ по договорам ГК с выбранной СК, номера которых есть в файле.

Для каждой строки ищет ЗХ с тем же договором, ФИО и датой рождения. Договор — любой из договоров ЗХ, включая прошлые (переход между ЮЛ).

Для найденных пар проверяет статус ЗХ и программу.

Для ненайденных строк ищет ту же персону по всем договорам ГК со СК: в другом договоре, с отличием в ФИО или в дате рождения.

ЗХ «Прикреплен», которым не нашлось пары в файле, получают категорию «Есть в системе, нет в СК».

Отдельно отмечаются дубли и задвоения, считается свод по договорам, результат сохраняется.

Как сравниваются значения

Для ФИО, программы и номера договора не должны учитываться только регистр, пробелы в начале и в конце, несколько пробелов подряд.

Любое другое отличие должно считаться расхождением: буквы (в том числе «е» и «ё»), точки, запятые, дефисы, подчеркивания, суффиксы. Разные значения: «Москва» и «Москва.», «Москва.» и «Москва..», «Москва» и «Москва_new», «Петров» и «Пётров».

ФИО в системе для сравнения должно собираться как «Фамилия Имя Отчество».

Категории

Каждая строка файла и каждый ЗХ «Прикреплен» должны попасть ровно в одну категорию.

| Категория | Когда присваивается | Расхождение? |
|---|---|---|
| Совпало | Пара найдена, ЗХ «Прикреплен», программа совпадает | нет |
| Есть в СК, нет в системе | Пара не найдена. Или найден ЗХ в статусе «Откреплен» — тогда комментарий «В системе откреплен» | да |
| Есть в системе, нет в СК | ЗХ «Прикреплен», которого нет в файле | да |
| Другое ЮЛ | Те же ФИО и дата рождения найдены в другом договоре ГК. В комментарии — оба номера договора | да |
| Расхождение в ФИО | Тот же договор и дата рождения, отличается одна часть ФИО (фамилия, имя или отчество). В комментарии — какая часть и оба значения | да |
| Расхождение в дате рождения | Тот же договор и ФИО, другая дата рождения. В комментарии — обе даты | да |
| Расхождение по программе | Основная программа в файле отличается от текущей программы ЗХ. В комментарии: «Отличие только в знаках», если совпадают буквы и цифры, иначе «Другая программа» | да |
| Доп. программа в СК | Строка с типом «Дополнительная», а такой программы у ЗХ нет | да |
| Дубль в списке СК | Вторая и следующие одинаковые строки файла (договор, ФИО, дата рождения, программа). Первая сверяется как обычно | да |
| Задвоение у СК | Одна персона в файле в разных договорах по основной программе | да |
| Дубль в системе | Два и более ЗХ «Прикреплен» с одинаковыми ФИО и датой рождения | да |
| В процессе у нас | Пара найдена, а ЗХ в статусе «в процессе» прикрепления, открепления или изменения | нет, для справки |
| Переход между ЮЛ | Пара найдена по прошлому договору ЗХ. Отметка добавляется к основной категории | нет, для справки |


Особые случаи

Если строке подходит несколько ЗХ, строка должна попасть в «Есть в СК, нет в системе» с комментарием «Найдено несколько ЗХ», а эти ЗХ — в «Дубль в системе».

Строки одного ЗХ по основной и дополнительной программе дублем не считаются.

Если в ФИО отличаются две части и больше, пара не ищется: строка попадает в «Есть в СК, нет в системе», ЗХ — в «Есть в системе, нет в СК».

ЗХ «в процессе», которых нет в файле, в список не попадают — только в свод, колонка «В процессе у нас».

Результат должен сохраняться на момент сверки и не пересчитываться при повторном открытии.

Статус сверки: «Обрабатывается» — пока идет сопоставление, «Готова» — результат сохранен, «Ошибка обработки» — сбой.

Не входит

Нечеткий поиск (опечатки в нескольких частях ФИО)

Изменение данных ЗХ в системе по результатам сверки

Критерии приемки

«ИВАНОВ  ИВАН ИВАНОВИЧ» в системе и «Иванов Иван Иванович» в файле с тем же договором и датой рождения — «Совпало».

«Петров Петр Петрович» в системе и «Петров Пётр Петрович» в файле — «Расхождение в ФИО», в комментарии — имя и оба значения.

Программа «Москва.» в файле и «Москва..» в системе — «Расхождение по программе» с комментарием «Отличие только в знаках».

Программа «Москва_new» в файле и «Москва» в системе — «Расхождение по программе».

ЗХ «Прикреплен», которого нет в файле, — «Есть в системе, нет в СК».

Строка файла по ЗХ в статусе «Откреплен» — «Есть в СК, нет в системе» с комментарием «В системе откреплен».

Строка файла по ЗХ «в процессе открепления» — «В процессе у нас», в «Итого расхождений» не входит.

Персона в файле в договоре одного ЮЛ, а в системе — в договоре другого ЮЛ ГК — «Другое ЮЛ» с обоими номерами договоров.

Персона в файле в договорах двух ЮЛ — «Задвоение у СК» в обеих строках.

Две одинаковые строки файла — первая сверяется, вторая получает «Дубль в списке СК».

Два ЗХ «Прикреплен» с одинаковыми ФИО и датой рождения — «Дубль в системе».

Строки одного ЗХ по основной и дополнительной программе дублем не считаются.

Как работает

Пока сверка выполняется, на экране индикатор I1; после завершения экран обновляется сам, без перезагрузки.

Пользователь смотрит свод по договорам. Клик по числу в колонке категории фильтрует список по договору и категории.

Пользователь просматривает список расхождений и фильтрует его по категории, договору или ФИО.

Шапка

ГК, СК, дата и время запуска, кто запустил, статус, ссылка на исходный файл, кнопка «Выгрузить в Excel» (FR-04).

Предупреждения

Должны отображаться над сводом, если условие выполняется:

| Код | Когда показывается |
|---|---|
| W1 | У ЮЛ ГК есть договоры с выбранной СК, которых нет в файле — сверка по ним не проводилась |
| W2 | По договору в файле в 2 раза больше людей, чем ЗХ «Прикреплен» в системе, или наоборот — возможно, массовое прикрепление или открепление не дошло до системы |


Свод по договорам

Строка на каждый договор и итоговая строка. Колонки: «Договор», «ЮЛ», «Страхователь (СК)», «В файле СК», «Прикреплен в системе», «В процессе у нас», «Совпало», по колонке на каждую категорию, «Итого расхождений» (без категорий «для справки»).

Список расхождений

Колонки: «Категория», «Договор», «ЮЛ», «ФИО (СК)», «ФИО (система)», «ДР (СК)», «ДР (система)», «Программа (СК)», «Программа (система)», «№ полиса СК», «Статус ЗХ», «Комментарий».

Отличающиеся значения должны подсвечиваться в обеих ячейках пары: например, «ФИО (СК)» и «ФИО (система)».

Категория должна выделяться цветом, категории «для справки» — нейтральным.

Фильтры: «Категория» (несколько значений), «Договор», поиск по ФИО, переключатель «Показывать для справки» (по умолчанию включен).

Сортировка по умолчанию — в порядке таблицы категорий (FR-02), затем по ФИО.

Если расхождений нет, вместо списка должно отображаться I2.

| W2 | Численность отличается в 2 раза и более | «По договору <номер> в файле СК <N> чел., в системе <M> чел. Возможно, массовое прикрепление или открепление не отражено» | Над сводом |

Отметки «обработано» и комментарии пользователя к строкам

Критерии приемки

Пока сверка выполняется, отображается I1; после завершения свод и список появляются без перезагрузки страницы.

В шапке отображаются ГК, СК, дата и время, кто запустил, статус и ссылка на исходный файл.

Если у ГК есть договор с СК, которого нет в файле, над сводом отображается W1 с номером договора.

Если по договору в файле 200 строк, а в системе 50 ЗХ «Прикреплен», отображается W2.

Клик по числу в своде фильтрует список по договору и категории.

В строке «Расхождение в ФИО» подсвечены «ФИО (СК)» и «ФИО (система)», остальные ячейки не подсвечены.

При выключенном «Показывать для справки» строки «В процессе у нас» и «Переход между ЮЛ» скрыты.

Если расхождений нет, отображается «Расхождений не найдено».

Как работает

Пользователь нажимает «Выгрузить в Excel» — кнопка активна только для сверки в статусе «Готова».

Скачивается файл «Сверка <ГК> <СК> <ДД.ММ.ГГГГ>.xlsx» (дата запуска сверки) со всем результатом, независимо от фильтров на экране.

Листы файла

| Лист | Что содержит |
|---|---|
| Свод по договорам | То же, что свод на экране, и строку «Итого». Под таблицей — дата сверки, ГК, СК и правила сверки: только «Прикреплен»; регистр и лишние пробелы не учитываются, остальные отличия — расхождение |
| Расхождения | То же, что список на экране; отличающиеся значения подсвечены, категории выделены цветом |
| Запрос в СК | Только категории, по которым ниже указан запрос. Колонки: «Категория», «№ договора», «Страхователь (СК)», «ФИО (СК)», «ДР (СК)», «№ полиса СК», «Программа (СК)», «Комментарий», «Что запросить у СК», «Ответ СК (дата / комментарий)» — пустая |


На всех листах: шрифт Arial, шапка с заливкой, фильтры, закрепленная шапка.

Что запросить у СК

| Категория | Текст в колонке «Что запросить у СК» |
|---|---|
| Есть в СК, нет в системе | Сообщить дату прикрепления и основание (письмо, заявка) |
| Есть в системе, нет в СК | Подтвердить прикрепление или сообщить дату открепления |
| Другое ЮЛ | Уточнить, в каком ЮЛ застрахован, даты открепления и прикрепления при переводе |
| Расхождение в ФИО | Подтвердить написание ФИО |
| Расхождение в дате рождения | Подтвердить дату рождения |
| Расхождение по программе | Подтвердить программу страхования |
| Доп. программа в СК | Подтвердить подключение доп. программы и основание |
| Дубль в списке СК | Уточнить, какой полис действующий |
| Задвоение у СК | Уточнить, в каком ЮЛ застрахован |


«Дубль в системе», «В процессе у нас» и «Переход между ЮЛ» на лист «Запрос в СК» не попадают — это вопросы к нашей стороне или справка.

Критерии приемки

Для сверки в статусе «Обрабатывается» кнопка «Выгрузить в Excel» неактивна.

Скачивается файл «Сверка <ГК> <СК> <дата>.xlsx» с листами «Свод по договорам», «Расхождения», «Запрос в СК».

При включенном фильтре на экране в файле все строки результата.

Итоги листа «Свод по договорам» совпадают со сводом на экране.

На листе «Запрос в СК» нет строк «Дубль в системе», «В процессе у нас», «Переход между ЮЛ»; колонка «Ответ СК» пустая.
