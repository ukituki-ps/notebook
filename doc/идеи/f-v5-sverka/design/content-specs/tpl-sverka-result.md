# Content spec — «Результат сверки»

Шаблон: `tpl-sverka-result`. Маршрут `/sverka/{runId}`. Экран читается сверху
вниз: что за сверка → всё ли в порядке → сколько расхождений → какие именно.

> Код `I1` в постановках перегружен (см. `tpl-sverka-launch.md`). В этом шаблоне
> `I1` — «Сверка выполняется…» из базовой v2 **и** «Действий с нашей стороны не
> найдено» из дополнения 3. Это разные состояния (`S-RES-PROCESSING` и
> `S-RES-ZX-NO-ACTIONS`), совпадает только литерал кода.

## 1. Анатомия

1. Ссылка «← К списку сверок».
2. `h1` «Результат сверки».
3. Шапка-метаданные: ГК, СК, когда запущена, кто запустил, статус, исходный
   файл, «Выгрузить в Excel».
4. Предупреждения W1/W2 (над сводом, только при выполнении условия).
5. Свод по договорам + KPI «Итого расхождений».
6. Фильтры списка.
7. Список расхождений (15 колонок) или пустое состояние I2.
8. Примечание о свежести данных ЗХ (под фильтрами, над списком).

## 2. Шапка

| Элемент | Текст / правило |
|---|---|
| Ссылка назад | ← К списку сверок |
| `h1` | Результат сверки |
| Мета: ГК | ГК: <название> |
| Мета: СК | СК: <название> |
| Мета: запуск | Запущена: ДД.ММ.ГГГГ, ЧЧ:ММ |
| Мета: автор | Кто запустил: <ФИО> (fallback — username) |
| Мета: статус | Статус: Обрабатывается · Готова · Ошибка обработки |
| Мета: файл | Исходный файл: <имя файла> (ссылка на скачивание, `download`) |
| Файл недоступен | Исходный файл: недоступен (файл удалён по сроку хранения) |
| Кнопка экспорта | Выгрузить в Excel |
| Экспорт недоступен | helper: Доступно после завершения сверки. |
| Экспорт pending | Готовим файл… (disabled, `aria-busy="true"`) |
| Экспорт ошибка | Не удалось подготовить файл. Попробуйте ещё раз. (inline, `role="alert"`) |

Статус — текст + нейтральный чип; цвет не единственный признак. В шапке нет
редактируемых полей и нет кнопок, кроме экспорта.

## 3. Предупреждения W1/W2

Блок `h2` «Предупреждения» (sr-only заголовок допустим, если предупреждений
несколько), над сводом. Каждое предупреждение — нейтральная плашка с меткой
«Предупреждение» и текстом постановки.

| Код | Текст (дословно) | Правило |
|---|---|---|
| W1 | В файле нет данных по договорам: <номера>. Сверка по ним не проводилась | номера через запятую, в порядке возрастания; при > 5 номерах — первые 5 + кнопка «Показать все (N)» |
| W2 | По договору <номер> в файле СК <N> чел., в системе <M> чел. Возможно, массовое прикрепление или открепление не отражено | N, M — целые с разделителем разрядов; «чел.» без склонения |

- W1 и W2 показываются одновременно, если оба условия выполнены.
- Предупреждение не блокирует просмотр и экспорт.
- В экспорт W1/W2 не добавляются (лист «Свод по договорам» содержит только
  дату, ГК, СК и правила сверки — FR-04).

## 4. Свод по договорам

| Элемент | Текст |
|---|---|
| `h2` | Свод по договорам |
| Helper | Нажмите на число, чтобы отфильтровать расхождения по договору и категории. |
| KPI (mobile и desktop) | Итого расхождений: N |
| KPI, второй | Договоров: M |
| `caption` (sr-only) | Свод по договорам: строки по договорам и итоговая строка |
| Итоговая строка | Итого |

Колонки в порядке:

1. Договор
2. ЮЛ
3. Страхователь (СК)
4. В файле СК
5. Прикреплен в системе
6. В процессе у нас
7. Совпало
8. Есть в СК, нет в системе
9. Есть в системе, нет в СК
10. Другое ЮЛ
11. Расхождение в ФИО
12. Расхождение в дате рождения
13. Расхождение по программе
14. Доп. программа в СК
15. Дубль в списке СК
16. Задвоение у СК
17. Дубль в системе
18. Итого расхождений

Правила:

- «Итого расхождений» не включает справочные категории («В процессе у нас»,
  «Переход между ЮЛ»).
- Число 0 отображается приглушённо и **не является** ссылкой/кнопкой.
- Число > 0 в колонке категории фильтрует список по этой категории и этому
  договору; число в «Итого расхождений» фильтрует только по договору.
- Фильтр через свод — обычная ссылка с query-параметрами (`?contract=…&category=…`),
  а не JS-only обработчик: состояние воспроизводимо, работает «назад».
- Доступное имя ссылки: «Показать 12 расхождений: Расхождение в ФИО, договор 0330R/045/5466/26».
- «Переход между ЮЛ» — не отдельная колонка свода, а маркер строки списка.

## 5. Фильтры списка

Панель фильтров над списком. На mobile сворачивается в `<details>`
«Фильтры» (открыта, если есть активный фильтр); на desktop — всегда раскрыта.

| Элемент | Текст | Поведение |
|---|---|---|
| Категория | Категория | `<details>` + нативные чекбоксы: 10 категорий расхождений + «В процессе у нас»; «Совпало» не фильтруется; счётчик выбранных в summary |
| Категория, счётчик | Категория: выбрано N | при N > 0; иначе «Категория: все» |
| Договор | Договор | нативный `<select>`: «Все договоры» + по одному |
| Поиск по ФИО | Поиск по ФИО | `<input type="search">` + кнопка «Очистить» |
| Поиск, placeholder | Начните вводить фамилию | поиск по ФИО (СК) и ФИО (система), без учёта регистра и лишних пробелов |
| Справка | Показывать для справки | нативный чекбокс, по умолчанию **включён** |
| Справка, helper | Справочные строки и отметка «Переход между ЮЛ» не входят в «Итого расхождений». | видимый текст, не tooltip |
| Сброс | Сбросить фильтры | показывается при активном фильтре |
| Счётчик результата | Показано N из M | `aria-live="polite"`, обновляется без перезагрузки |

Правила:

- Несколько выбранных категорий объединяются по «ИЛИ»; фильтры между собой —
  по «И».
- Выключение «Показывать для справки» скрывает строки «В процессе у нас» и
  маркеры «Переход между ЮЛ», если у строки нет другой причины показываться.
- Фильтры — часть URL: `category` (repeatable), `contract`, `q`, `ref=0|1`.
  «Сбросить» возвращает `/sverka/{runId}` без query.
- При смене фильтра список не перезагружается с сервера (клиентская фильтрация
  снимка, OD-10).
- Пустой результат фильтра ≠ I2: см. §7.

## 6. Список расхождений

| Элемент | Текст |
|---|---|
| `h2` | Расхождения |
| Счётчик | Показано N из M (или «N расхождений») |
| `caption` (sr-only) | Расхождения: категория, договор, застрахованный, данные СК и системы, договоры и заявки ЗХ |
| Примечание о свежести | Данные по договорам и заявкам ЗХ — на момент открытия экрана, а не на момент сверки. |

Колонки в порядке:

| # | Колонка | Содержимое |
|---|---|---|
| 1 | Категория | категория + маркер «Переход между ЮЛ» (если есть) |
| 2 | Договор | номер договора строки; для «Есть в системе, нет в СК» — договор ЗХ |
| 3 | ЮЛ | юридическое лицо |
| 4 | ФИО (СК) | значение из файла или «—» |
| 5 | ФИО (система) | значение из системы или «—» |
| 6 | ДР (СК) | ДД.ММ.ГГГГ или «—» |
| 7 | ДР (система) | ДД.ММ.ГГГГ или «—» |
| 8 | Программа (СК) | значение из файла или «—» |
| 9 | Программа (система) | значение из системы или «—» |
| 10 | № полиса СК | значение или «—» |
| 11 | Статус ЗХ | Прикреплен · Откреплен · в процессе прикрепления/открепления/изменения · «—» |
| 12 | Комментарий | текст постановки или «—» |
| 13 | Договоры ЗХ | все договоры ЗХ, включая прошлые; каждый номер — ссылка |
| 14 | Заявки ЗХ | 3 последние заявки; остальные — «еще N» |
| 15 | Действия с нашей стороны | «Есть заявки» или «Действий с нашей стороны не найдено» |

Сортировка: фиксированная — порядок категорий из FR-02, затем по ФИО; внутри
равных — по договору. Пользовательской сортировки нет (не входит в постановку).

Строки категории «Совпало» в список **не попадают**: они учитываются только в
своде. Список — расхождения и справочные категории (DD-05, OQ-D3).

### 6.1. Подсветка отличий

- Подсвечиваются **обе** ячейки пары: ФИО (СК)/ФИО (система), ДР (СК)/ДР
  (система), Программа (СК)/Программа (система) — только если обе стороны
  присутствуют и различаются.
- Подсветка: фон `--danger-bg`, внутренняя левая граница `--danger` 3 px;
  текст остаётся `--text` (контраст AA). Цвет не единственный признак: ячейка
  получает `data-diff="fio|dr|program"` и sr-only пометку «значение отличается».
- Для категорий без пары («Есть в СК, нет в системе», «Есть в системе, нет в
  СК») подсветки нет: сравнивать не с чем, смысл несёт категория и
  комментарий.
- Регистр и лишние пробелы в подсветке не участвуют — сравнение уже
  нормализовано (FR-02); подсвечивается только реальное отличие.

| Другое ЮЛ | расхождение |
| Расхождение в ФИО | расхождение |

Тон — 2 значения (нейтральный/внимание) + текстовый ярлык. 13 разных цветов не

### 6.3. Комментарии (дословно из постановки)

- «В системе откреплен»
- «Отличие только в знаках» / «Другая программа»
- «Найдено несколько ЗХ»
- «Дубль в системе»
- для «Другое ЮЛ» — оба номера договоров
- для «Расхождение в ФИО» — какая часть и оба значения
- для «Расхождение в дате рождения» — обе даты

## 7. Состояния экрана

| Состояние | Что видно |
|---|---|
| `S-RES-LOADING` | шапка + «Загружаем результат сверки…»; свод/список скрыты |
| `S-RES-PROCESSING` (I1) | шапка со статусом «Обрабатывается», файл, disabled экспорт; вместо свода и списка: `h2` «Сверка выполняется», текст «Сверка выполняется. Результат появится автоматически» |
| `S-RES-ERROR` | шапка со статусом «Ошибка обработки»; блок «Сверка завершилась ошибкой обработки» + причина (если есть) + «Загрузите файл заново или обратитесь к администратору»; экспорт disabled, свода и списка нет |
| `S-RES-NO-DATA` | шапка; блок «Результат сверки недоступен» + «Файл и результат хранятся ограниченное время.»; ссылка назад |
| `S-RES-READY` | шапка, W1/W2 (если есть), KPI, свод, фильтры, список |
| `S-RES-EMPTY` (I2) | шапка, W1/W2, свод, вместо фильтров и списка — «Расхождений не найдено» + «Проверены все строки файла и прикреплённые ЗХ» |
| `S-RES-FILTER-EMPTY` | шапка, свод, фильтры; вместо списка — «По выбранным фильтрам расхождений нет» + «Сбросить фильтры» |
| `S-RES-EXPORT-DISABLED` | кнопка disabled + helper «Доступно после завершения сверки» |
| `S-RES-EXPORT-PENDING` | «Готовим файл…», disabled |
| `S-RES-EXPORT-ERROR` | inline-ошибка над списком, кнопка снова активна |

I2 показывается **вместо списка**, но свод остаётся. Если расхождений нет, но
W1/W2 есть — предупреждения остаются видимыми.

## 8. Договоры и заявки ЗХ

| Элемент | Правило |
|---|---|
| Договоры ЗХ, пусто | — |
| Договор, ссылка | номер — ссылка, `target="_blank"`, `rel="noopener noreferrer"`; sr-only «откроется в новой вкладке» |
| Заявки ЗХ, строка | № <номер> · <тип> · <статус> · ДД.ММ.ГГГГ |
| Тип заявки | прикрепление · открепление · изменение |
| Статус заявки | значение из системы как есть (названия уточняются на груминге, OQ доп. 3) |
| 3 последние | сортировка по дате заявки, новые сверху |
| Остальные | кнопка «еще N» (N = всего − 3), раскрывает все заявки в строке; после раскрытия — «Свернуть» |
| Склонения | еще 1 заявка / еще 2 заявки / еще 5 заявок |
| Нет заявок | «Действий с нашей стороны не найдено» в колонке 15; в колонке 14 — «—» |
| Есть заявки | «Есть заявки» в колонке 15 |
| Свежесть | данные читаются на момент открытия экрана; заявка, созданная после сверки, появится при следующем открытии |
| «Есть в СК, нет в системе» | если ЗХ найден по ФИО+ДР в любых статусах и с любыми СК — показать его договоры и заявки; иначе «Действий…» |
| Excel | в выгрузке те же колонки, но **все** заявки, без «3 последние», через перенос строки; на листе «Запрос в СК» этих колонок нет |

## 9. Форматы, длинные значения, большие таблицы

- Даты `ДД.ММ.ГГГГ`; дата+время `ДД.ММ.ГГГГ, ЧЧ:ММ`; ISO — только в URL/API.
- Числа: неразрывный пробел как разделитель разрядов; `font-variant-numeric:
  tabular-nums`.
- ФИО/программы/номера **не обрезаются**: перенос по словам и
  `overflow-wrap:anywhere`. Максимальные проверенные значения — в
  `design/fixtures/result-ready.json` (`long_values`).
- Номера договоров и заявок — `white-space: nowrap`, чтобы не рвались в
  середине; при нехватке ширины — горизонтальный скролл таблицы.
- Имя файла — единственное значение, которое можно обрезать: середина,
  многоточие, полное имя в `title` и в доступном имени.
- Большие таблицы: первый рендер — первые 200 строк, далее кнопка «Показать
  ещё 200» (и счётчик «Показано N из M»); `content-visibility: auto` для
  строк. Фильтры работают по всему снимку, не только по отрендеренным строкам.
- Пустые значения — «—»; `sr-only` поясняет «значение отсутствует».

## 10. Мобильный (mobile-first, 360×640)

### Above the fold

- Ссылка назад, `h1`, строка «ГК — СК», статус, «Итого расхождений: N».
- Если есть W1/W2 — плашка предупреждения выше KPI; текст переносится и не обрезается.
- Если идёт обработка — заголовок «Сверка выполняется» и текст.
- Свод и список — ниже; свод горизонтально скроллится, «Договор» закреплён
  слева.

### Список расхождений (< 768 px)

Строка таблицы превращается в карточку:

1. Категория + маркер «Переход между ЮЛ».
2. Договор · ЮЛ.
3. Пары «СК → система»: ФИО, ДР, Программа. Обе стороны пары подсвечены при отличии;
   значение системы подписано «в системе».
4. № полиса · Статус ЗХ.
5. Комментарий.
6. Договоры ЗХ (ссылки) · Заявки ЗХ (3 + «еще N») · Действия с нашей стороны.

Второстепенные поля (ЮЛ, № полиса) визуально приглушены, но не скрыты; кнопка
«Подробнее» раскрывает длинный комментарий. Данные не теряются.

### Фильтры

`<details>` «Фильтры»; если фильтр активен — открыт и в summary видно
«Фильтры: N». Кнопка «Сбросить фильтры» — внутри панели и в пустом состоянии.

### Тап-цели

Все интерактивные элементы ≥ 44×44 px; ссылки в таблице имеют вертикальные
отступы, чтобы не слипаться.

## 11. Доступность

- Семантика: `<table>` + `<caption>` + `<th scope="col">`; мобильная карточка
  сохраняет те же подписи (не только визуальные).
- Ссылки в новой вкладке: `target`, `rel`, sr-only «откроется в новой вкладке».
- Подсветка отличий дублируется текстом (`sr-only` «значение отличается»).
- Счётчики и результаты фильтрации — `aria-live="polite"`; не чаще одного
  объявления на действие.
- «Показать все (N)», «еще N», «Показать ещё 200» — кнопки с `aria-expanded`.
- При завершении фоновой сверки: `aria-live="polite"` «Сверка готова. Расхождений: N»,
  затем фокус остаётся там, где был (не перехватывается).
- `prefers-reduced-motion`: автообновление без анимаций.
